# Commit-on-turn

This project ships from `main`. There is no PR review flow for routine work. Per-turn commit-and-push is the model:

> **After any assistant turn that modifies tracked files, stage those files explicitly, commit with a clear one-line message, and push to `origin/main` before signing off.**

A Stop hook ([auto-commit-push.sh](auto-commit-push.sh), wired up in [settings.json](settings.json)) acts as a safety net — if a turn ends with staged-but-uncommitted changes, the hook commits and pushes them with an auto-generated message. In normal flow the hook is a no-op.

# The flow (Claude's responsibility)

Run these as the final step of any turn that touched tracked files:

1. **Snapshot state.** `git status --short` to see what's dirty. `git diff` if you need to remember what you changed.
2. **Stage deliberately, by file.** `git add path/to/file.ts path/to/other.md`. Do **not** use `git add -A` or `git add .` — see the volatile-file rules below.
3. **Write the message.** One line, present tense, focused on the *why*. Match the existing log's tone (skim `git log -10 --oneline`). The auto-hook's fallback message is ugly on purpose; a thoughtful per-turn message keeps history readable.
4. **Commit.** Include `Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>`.
5. **Push.** `git push origin main`. If rejected (non-fast-forward), do not force — pull, reconcile, or stop and ask.

# What never gets auto-staged

The repo contains files that change for non-session reasons. Never stage these without an explicit ask:

- `tools/bots/elo/results.json` — overwritten by every tournament run, in flight during long runs.
- `site/public/puzzles/pool*.jsonl` and `pool*.meta.json` — generated by the curator (already `.gitignore`d, but listed for clarity).
- Any file the user is concurrently editing (check `git status` at the start of your turn; if a file you didn't change shows as modified, leave it alone).

# What never gets committed at all

- `.env`, `*.key`, `credentials*.json`, anything with the shape of an API token — refuse and warn even if staged.
- Bypassing `--no-verify`. If a pre-commit hook fails, fix the underlying issue and make a new commit. Do not amend after a failed hook.
- Force-push to `main`. Not with `--force`, not with `--force-with-lease`, not with `+main`. History rewriting is a conversation, not an action.

# Disabling the safety net

For sessions where the per-turn cadence is wrong (e.g. a long exploration where you want to commit only at the end), export `CLAUDE_AUTO_COMMIT_DISABLED=1` before starting. The hook becomes a no-op.

# Why a hook *and* a convention

The hook alone produces ugly auto-messages and can't make smart staging decisions. The convention alone forgets sometimes. Together: Claude commits thoughtfully when there's something to say; the hook catches anything left staged at turn-end.
